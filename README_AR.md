# TP1 — التوقيعات المجمّعة BLS في إنترنت الأشياء

## 1. هدف التجربة
نحاكي مجموعة حساسات ترسل قراءاتها موقعة رقميًا إلى بوابة IoT. نستخدم BLS لتجميع التواقيع الفردية في توقيع واحد، ثم نقارن حجم التوقيع وزمن التحقق مع Ed25519.

> تنبيه: هذا مشروع تعليمي، وليس كودًا إنتاجيًا. توثيق py_ecc يحذّر من أن المكتبة لم تخضع لتدقيق أمني كامل. لا تستخدم المفاتيح أو الكود هنا لحماية نظام حقيقي.

## 2. المتطلبات
- Python 3.11 أو أحدث (يتوافق py-ecc 8.0.0 مع Python 3.11–3.13 حسب بيانات الحزمة).
- pip.
- MQTT اختياري للتجربة الشبكية: Mosquitto وpaho-mqtt.

## 3. إعداد البيئة على Windows PowerShell
افتح PowerShell داخل مجلد المشروع:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

إذا لم يكن Python 3.11 مثبتًا، استخدم نسخة مثبتة لديك ومتوافقة؛ افحصها باستخدام `python --version`.

## 4. الخطوة الأولى: تشغيل التحقق الصحيح والتلاعب

```powershell
python step1_demo.py
```

النتيجة المتوقعة منطقيًا:
- التحقق من المجموعة الصحيحة يعيد `True`.
- تعديل رسالة حساس بعد توقيعها يجعل التحقق يعيد `False`.
- استبدال المفتاح العام بمفتاح لا يطابق التوقيع يجعل التحقق يعيد `False`.
- حجم توقيع BLS المجمّع أصغر من مجموع أحجام تواقيع BLS الفردية.

## 5. تشغيل الاختبارات الآلية

```powershell
python -m unittest -v test_tp1.py
```

يجب أن تنجح اختبارات التوقيع الفردي الصحيح، ورفض الرسالة المعدّلة، والتحقق من التوقيع المجمع، ورفض الرسالة المعدّلة أو المفتاح العام الخاطئ.

## 6. القياس والمقارنة

```powershell
python benchmark.py
```

ينشئ الملف `benchmark_results.csv` للأحجام 2 و8 و32 و128 حساسًا. يُسجّل الزمن المحلي الوسيط وحجم توقيع BLS المجمّع مقارنة بمجموع تواقيع Ed25519 الفردية. لا تنقل أرقامًا من جهاز آخر؛ شغّل التجربة وسجّل أرقام جهازك.

## 7. عرض MQTT الاختياري

أولًا شغّل Mosquitto محليًا على المنفذ 1883. ثم في نافذة PowerShell الأولى:

```powershell
python generate_fleet.py
python mqtt_gateway.py
```

وفي نافذة PowerShell ثانية، من مجلد المشروع نفسه:

```powershell
python mqtt_publisher.py
```

البوابة تجمع توقيعات الحساسات العشرة، وتتحقق من التجميع. يلزم أن تعمل البوابة قبل الناشر حتى لا تفوت رسائل التجربة. هذه الإعدادات بلا TLS أو مصادقة على وسيط MQTT لتسهيل التعلّم محليًا فقط؛ لا تعرّض الوسيط للإنترنت.

ملفات المفاتيح `sensor_private_keys.json` و`public_registry.json` تُنشأ محليًا. لا ترفع الملف الخاص إلى Git. في تطبيق حقيقي يجب حماية المفاتيح، وتأمين MQTT، ومصادقة الأجهزة وإدارة دورة حياة المفاتيح.

## 8. كيف يعمل BLS هنا؟
1. كل حساس يملك مفتاحًا خاصًا ومفتاحًا عامًا.
2. يحوّل الحساس رسالته إلى بايتات JSON ثابتة الترتيب ثم يوقّعها.
3. تجمع البوابة التوقيعات باستخدام `Aggregate`.
4. تتحقق من التوقيع المجمع على رسائل مختلفة باستخدام `AggregateVerify`.
5. يجب أن تكون المفاتيح العامة مسجّلة وموثّقة. يستخدم المشروع Proof of Possession (PoP) ويتحقق منه عند تسجيل المفتاح، لتجنب قبول مفاتيح عامة غير موثوقة بلا فحص.

## 9. ماذا نناقش في التقرير؟
- المنهجية: BLS من `py_ecc`، وEd25519 من `cryptography`، وعدد الحساسات n = 2, 8, 32, 128.
- النتائج: جدول `benchmark_results.csv`، ونتيجة الاختبارات، وحجم التوقيع المجمّع مقارنة بالتواقيع الفردية.
- المناقشة: ضغط حجم الاتصال مقابل كلفة التحقق والتجميع؛ حدود التجربة؛ لماذا تحتاج الأجهزة محدودة الموارد إلى موازنة الأمان والطاقة والاتصال.
- افصل بوضوح بين ما كتبناه نحن (كود المحاكاة والاختبارات والقياس) وما وفرته المكتبات (عمليات BLS وEd25519 التشفيرية الأساسية).

## 10. ملاحظة علمية
في الاختبار، الرسائل متميزة لكل حساس؛ لذلك نستخدم `AggregateVerify(public_keys, messages, aggregate_signature)`. لا تستبدل ذلك تلقائيًا بـ `FastAggregateVerify`؛ فهذه الأخيرة تخص التحقق السريع من تواقيع متعددة على الرسالة نفسها، وتستلزم تحقق Proof of Possession لكل مفتاح عام.
